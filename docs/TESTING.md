# Тестирование

Здесь перечислено, что в текущей бета-версии проверено, каким способом — и что **не** проверено. Документ намеренно подробен в части ограничений: проекту нужны отзывы именно там, где проверки пока нет.

## Итог

| | |
|---|---|
| Автоматические тесты | 132, проходят на Python 3.12 и 3.13, прогон около 4 минут |
| Реальные серверы | одна подписка Remnawave, 15 серверов VLESS · TCP · REALITY: более 1000 сквозных проверок, 0 неудач, 0 ложных подозрений |
| Telegram | настоящий Bot API через SOCKS5-прокси: доставка уведомлений, перезапуск посреди инцидента, обрыв связи |
| Cheburcheck | заменитель с записанными реальными ответами + живые запросы к сервису |
| Установщик | полный прогон в окружении Ubuntu 24.04 (chroot) с заменителем systemd |
| Не проверено | работа из российской сети, настоящий systemd и перезагрузка, часть транспортов — см. [ниже](#что-не-проверено) |

## Как запустить тесты

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt pytest pytest-asyncio && pip install -e .

XRAY_BIN=/путь/к/xray pytest             # все тесты
pytest -m "not network"                  # без обращений в интернет
pytest tests/unit                        # только модульные, несколько секунд
```

Бинарник Xray-core берётся из переменной `XRAY_BIN`, из `/usr/local/bin/xray` или из `PATH`. Без него тесты, которым нужен стенд, пропускаются.

## Как устроен стенд

Интеграционные тесты запускают настоящий код против заменителей внешних систем (`tests/fakes`):

| Заменитель | Что делает |
|---|---|
| Стенд Xray | настоящие серверы Xray на loopback: VLESS+REALITY+Vision, Trojan+WS+TLS, VLESS+WS, Shadowsocks, Hysteria2; сайт-прикрытие; цель для запросов через туннель |
| Реле с помехами | TCP-прослойка, имитирующая поведение DPI: молчание после ClientHello, сброс соединения, остановка потока после 16 КБ |
| Панель Remnawave | отдаёт подписку во всех форматах; режимы: подписка истекла, требуется HWID, лимит устройств, HTTP 500, HTML-страница, 404, обрыв соединения |
| Telegram Bot API | принимает запросы настоящего aiogram и выдаёт обновления; режимы: 502, обрыв, 429, 403 |
| Cheburcheck | воспроизводит записанные ответы сервиса; режимы: 5xx, 429, изменённый формат, обрыв потока |
| SOCKS5-прокси | с авторизацией; записывает, к каким адресам через него обращались |

Образцы подписок в `tests/fixtures/sub` получены из ответов реальной панели Remnawave; адреса, ключи, идентификаторы и названия в них заменены вымышленными. Образцы в `tests/fixtures/cheburcheck` — ответы публичного API cheburcheck.ru для общеизвестных адресов.

## Что покрыто

| Область | Тестов | Что проверяется |
|---|---|---|
| Автомат состояний | 14 | все переходы, пороги, «нет вердикта», сброс после простоя |
| Форматы подписки | 18 | четыре формата дают одинаковый набор серверов; IPv6; смешанные протоколы; заглушки; дедупликация |
| Конфигурация, секреты, сводки | 12 | проверка параметров, шифрование, маскирование в журнале, сводки и выводы по данным Cheburcheck |
| Сценарии мониторинга | 21 | подтверждение DOWN и RECOVERED, заморозка при проблемах сети, массовый отказ, нестабильный сервер, исключения, перезапуск |
| Проверки на стенде Xray | 16 | все протоколы стенда; неверные учётные данные; помехи на пути; остановленный сервер; сбой DNS; отсутствие Xray |
| Жизненный цикл подписок | 13 | импорт, обновление, удаление и возврат серверов, смена адреса, отказ панели, истёкшая подписка |
| Cheburcheck | 11 | когда запрашивается, кеш, недоступность сервиса, досылка данных, лимиты |
| Интерфейс Telegram | 11 | доступ только владельца, меню, подписки, карточка сервера, исключения, настройки |
| Доставка и прокси | 10 | очередь, обрыв связи, повтор, маршрут через прокси, смена прокси |
| Обслуживание и командная строка | 5 | срок хранения, резервные копии, восстановление, проверка конфигурации |
| Сервис как процесс | 1 | запуск `python -m rwmon run`, падение и восстановление стенда, перезапуск, SIGKILL, уведомления systemd |

Ключевые сценарии защиты от ложных срабатываний, закреплённые тестами:

- одна или две неудачи не дают уведомления; DOWN — только после заданного числа неудач подряд;
- при отсутствии сети у самого мониторинга результаты отбрасываются, в том числе если сеть пропала посреди цикла;
- сбой DNS мониторинга не превращается в падение серверов;
- истёкшая подписка даёт одно сообщение о подписке, а не падение всех серверов;
- многократная ручная проверка не ускоряет объявление DOWN;
- после перезапуска уведомления не повторяются, а неотправленные — доставляются;
- чужие пользователи и групповые чаты не получают ни одного ответа.

## Проверка на реальных системах

**Реальная подписка.** Панель Remnawave с включённым лимитом устройств, 16 записей → 15 серверов. Подписка разобрана во всех четырёх форматах; наборы серверов совпали. Сервис наблюдал за серверами около часа с интервалом 60 секунд: 945 проверок, все успешные, ни одного перехода в SUSPECT; отклик туннеля 144–5790 мс, в среднем 687 мс. Каждая проверка проходила полный путь до запроса через туннель. Прогон выполнялся из дата-центра за пределами России.

**Telegram.** Сервис работал с настоящим Bot API через SOCKS5-прокси с авторизацией; прокси зафиксировал соединения только с `api.telegram.org:443`. Проверены: уведомление о запуске, падение и восстановление серверов стенда, перезапуск сервиса посреди инцидента (повторного уведомления нет), отключение прокси на несколько минут (сообщения дождались в очереди и были доставлены), предупреждение о нестабильном сервере и о скором истечении подписки.

**Cheburcheck.** Для заведомо нерабочей записи (реальный хост, закрытый порт) сервис объявил DOWN и приложил к уведомлению реальные замеры региональных сканеров и статические данные.

**Установщик.** Полные прогоны `install.sh` в окружении Ubuntu 24.04 LTS (chroot с базовым образом системы) с заменителем systemd, который действительно запускает процесс службы из установленного unit-файла:

| Сценарий | Результат |
|---|---|
| Команда из README на чистой системе (установщик и исходники загружаются с GitHub) | установка от начала до конца, служба запущена |
| Чистая установка без параметров | программа установлена, служба не запущена, показано, что заполнить |
| Повторный запуск с параметрами в окружении | недостающие параметры записаны, служба запущена |
| Интерактивная установка через псевдотерминал | вопросы заданы, неверный ввод переспрошен, токен и адрес прокси на экран не выводятся |
| Обновление работающей установки | конфигурация не изменена, создана копия базы, служба перезапущена, лишние версии удалены |
| Новая версия не запускается | возврат к прежней версии и прежней базе |
| Ошибка на этапе сборки | прежняя версия не затронута и продолжает работать |
| Другая ОС, отсутствие systemd | установка отклонена с понятным сообщением |
| Токен отклонён Telegram | установка завершается с явным указанием, что исправить |
| Удаление и полное удаление | выполнены, полное удаление требует подтверждения |

Файл службы проверен `systemd-analyze verify`; оценка `systemd-analyze security` — 3.1 (OK).

## Что не проверено

| Что | Почему | Чем помочь |
|---|---|---|
| Работа из российской сети | тестовая среда находится за пределами России | запустите на VPS в России и сообщите о ложных срабатываниях и пропущенных падениях |
| Реальная блокировка ТСПУ | воспроизводилась только по сетевым признакам на стенде | приложите к issue результат проверки по уровням из карточки сервера |
| Настоящий systemd, автозапуск после перезагрузки | в тестовой среде нет systemd | `sudo reboot` и проверка, что пришло «Мониторинг запущен» |
| Сквозная проверка XHTTP, gRPC, HTTPUpgrade, mKCP | в проверенной подписке таких серверов нет | сообщите, проходит ли проверка на ваших серверах |
| Trojan, Shadowsocks, Hysteria2 на реальных серверах | проверены только на локальном стенде | то же |
| HTTP-прокси для Telegram | проверен только SOCKS5 | — |
| IPv6, архитектура aarch64 | нет в тестовой среде | — |
| Работа дольше нескольких часов, подписки на сотни серверов | не хватило времени | сообщите о потреблении памяти и длительности цикла |
| Игнорирование чужих пользователей с настоящим Telegram | нужен второй аккаунт; проверено на заменителе Bot API | напишите боту с другого аккаунта |

## Проверка на своём сервере

1. Установите сервис и убедитесь, что в самопроверке все строки `OK` (для Cheburcheck допустимо `--`).
2. Отправьте боту `/start`, затем ссылку на подписку. Через минуту у всех серверов в списке должен появиться результат.
3. В «📊 Статус мониторинга»: самоконтроль ✅, сквозная проверка ✅, маршрут Telegram — ваш прокси, проверки — напрямую.
4. Напишите боту с другого аккаунта — ответа быть не должно.
5. Перезагрузите сервер — после загрузки должно прийти «Мониторинг запущен» с длительностью простоя.
6. По возможности закройте на пару минут порт на одном из своих серверов: DOWN должен прийти через 1,5–2 минуты, после открытия порта — RECOVERED.
7. Через сутки посмотрите «📋 История событий»: если есть SUSPECT без видимой причины, увеличьте таймауты или порог и, пожалуйста, сообщите об этом.
