# Участие в проекте

Спасибо за интерес к rw-monitor. Проект находится в стадии **бета**, и самое ценное сейчас — отзывы из реальной эксплуатации: ложные срабатывания, пропущенные падения, проблемы установки.

## Сообщить об ошибке

Создайте [issue](https://github.com/Rrezzak09VPN/rw-monitor/issues/new/choose) и приложите:

- версию (`sudo rwmon --version`), ОС и версию Python;
- что вы сделали, что ожидали и что произошло;
- вывод `sudo rwmon selftest`;
- для проблем с проверкой сервера — текст из карточки сервера («ℹ️ Подробности»): протокол, транспорт и результаты по уровням;
- фрагмент журнала: `journalctl -u rw-monitor -n 100 --no-pager`;
- для проблем установки — вывод установщика целиком.

> [!IMPORTANT]
> **Перед отправкой уберите всё личное.** Журнал сервиса маскирует токен бота, ссылки подписок и UUID, но адреса и названия ваших серверов в нём остаются. Не публикуйте токены, ссылки подписок, UUID, ключи, адреса прокси с паролем и адреса своих серверов.

Если ошибка связана с разбором подписки, не прикладывайте саму подписку. Достаточно указать формат (ссылки, Xray JSON, Mihomo, sing-box), протокол и транспорт проблемной записи, заменив адрес, UUID и ключи вымышленными.

## Уязвимости

Не описывайте уязвимость в открытом issue. Сообщите о ней приватно: вкладка **Security → Report a vulnerability** в репозитории. Укажите, как воспроизвести проблему и к чему она приводит.

## Предложить изменение

1. Для заметных изменений сначала откройте issue и опишите идею — так проще договориться о подходе.
2. Сделайте форк и ветку от `beta`. Запросы на слияние принимаются в ветку `beta`.
3. Подготовьте окружение:

   ```bash
   python3 -m venv .venv && . .venv/bin/activate
   pip install -r requirements.txt pytest pytest-asyncio ruff && pip install -e .
   ```

4. Убедитесь, что проходят проверки:

   ```bash
   ruff check rwmon tests
   XRAY_BIN=/путь/к/xray pytest
   ```

5. Добавьте тест на исправленную ошибку или новое поведение и строку в раздел «Не выпущено» файла [CHANGELOG.md](CHANGELOG.md).

### На что обращать внимание

- **Достоверность.** Изменение не должно позволять объявить сервер недоступным по одной неудаче или из-за проблем самого мониторинга. Сомнение трактуется как «нет вердикта».
- **Маршруты.** Проверки серверов никогда не идут через прокси.
- **Секреты.** Ничего секретного в журнале, в сообщениях Telegram и в репозитории. Тестовые данные — только вымышленные.
- **Простота.** Один процесс, один файл данных, минимум зависимостей. Новая зависимость требует обоснования.
- **Тексты для владельца** — на русском языке; комментарии в коде и сообщения журнала — на английском.
- **Версии зависимостей** закреплены в `requirements.txt`; обновление — отдельным изменением с прогоном тестов.

Устройство проекта описано в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), состояние тестов — в [docs/TESTING.md](docs/TESTING.md).
